# 首播与播放器内存优化复测（2026-11-13）

本轮接续 [首轮性能报告](runtime-performance.md)。主要收益来自 HEVC 硬件解码路径选择；没有更换播放器、预加载下一集或减少身份验证。

## 测量条件

Windows x64 Release，NVIDIA GeForce RTX 4060，24 逻辑 CPU。使用同一授权剧集及既有 CLI、保存身份只读恢复；收藏写入、云端进度上传均关闭，静音/零音量。独立测试窗口位于屏幕外，禁止激活并禁用自身物理输入，用户实例未替换或重启。各轮 foreground_unchanged=true。

同一流程覆盖新闻样例 53 源/1590 条、720p 播放/暂停、三次切集/跳转、480p/360p/720p、真实 EOS/恢复、隐藏、关闭及页面/设置切换。播放和暂停各约 8 秒，其余阶段约 5 秒。内存为进程树私有提交；CPU 为整机口径，短命子进程和采样间峰值可能遗漏。未清系统缓存，网络及片段复杂度会波动。

## 内存归因及结果

单位 MiB，阶段末采样值；每列一次完整轮，不能当作长期均值。

| 阶段 | D3D12 基线 | 仅清共享帧，D3D12 | 清帧及并行初始化，显式 D3D11 |
| --- | ---: | ---: | ---: |
| 初始新闻页 | 221.1 | 222.2 | 226.2 |
| 首次 720p 播放 | 414.8 | 406.0 | 335.5 |
| 暂停 720p | 422.2 | 410.7 | 340.4 |
| 480p 播放 | 415.5 | 414.7 | 326.2 |
| 360p 播放 | 408.1 | 409.7 | 318.6 |
| 重新选择 720p | 425.5 | 427.9 | 341.1 |
| 关闭播放器 | 429.9 | 427.7 | 337.1 |
| 页面切换后 | 421.1 | 420.8 | 298.0 |

清共享帧单独没有显著降低总保留内存，不能将主要收益归给这一修复。实际解码器原为 d3d12h265dec；保持同一 HEVC/AAC 输入路线，显式改为 d3d11h265dec 后，首次播放相比紧邻 D3D12 轮减少约 70.5 MiB（17%），页面切换后减少约 122.8 MiB（29%）。AAC 仍由 avdec_aac 解码。

只读 VirtualQueryEx 汇总测试主进程的区域种类和大小，不读取内存内容或输出地址。页面切换后，MEM_PRIVATE 区域提交合计从 323.9 降到 217.4 MiB，MEM_IMAGE 从 528.0 降到 357.5 MiB，MEM_MAPPED 约 34.6/34.5 MiB。这些区域统计不是私有提交/实际驻留页或 GPU 显存，不能与上表相加，也不能据此确定某个堆泄漏。

相同首播阶段 CPU 为 D3D12 1.76%、D3D11 2.08%；其他阶段与最终默认轮存在波动，没有稳定 CPU 改善证据。结论是本机内存改善，不能承诺所有 GPU 同等收益。

## 最小实现

- Video Drop 在停止管线并回收工作线程后清空共享 Frame。renderer 可以继续持有 Arc，但不能继续钉住已停止的 GstSample。新增测试在修复前复现失败、修复后通过。
- 本地 GStreamer 初始化与原有取源握手并行，使用 scoped thread 回收；没有移除取源前后身份核对及媒体边界检查。新增分阶段数字诊断。
- 当 D3D11 和 D3D12 HEVC 工厂都存在且可选时，优先 D3D11；保留其余解码候选，显式 GST_PLUGIN_FEATURE_RANK 优先。不固定用户显卡、不持久修改系统环境，也不承诺运行中 GPU 故障自动恢复。
- 原有 EOS 退避、封面缓存范围和 CLI 单线程优化继续保留。

## 首播和操作时延

基线首播 6584ms，显式 D3D11 轮 5202ms，最终默认轮 8332ms。总体波动明显，不能宣称首播稳定缩短。首播还包含业务云端断点核对、取源、管线初始化和断点跳转，并非单一解码耗时。

本地引擎初始化原串行耗时 227–318ms，并行轮实际初始化 303–325ms，但取源完成后的等待为 0ms；这部分等待已被重叠。最终默认轮 helper 2045ms、管线准备 2053ms，表明剩余延迟仍受网络/管线及断点恢复影响。继续优化需针对这些阶段，不能通过跳过账号核对掩盖。

显式 D3D11 轮三次切集首帧中位数 1709ms、跳转 1039ms；最终默认轮分别 2168ms、717ms。样本各三次，且存在 3828ms 跳转高值，不是长期 SLA。CLI 状态查询中位数分别 65/73ms，包含进程启动及观察器开销。

## 验证及失败边界

1. 显式 D3D11 完整流程通过：真实帧/音频推进、三次切集/跳转、三档清晰度、EOS/seek 恢复、隐藏/释放及切页。它验证的是最终选用的解码路径，不能冒充最终默认二进制完整轮。
2. 最终默认策略实际选到 D3D11，720p 339.2 MiB，三次切集/跳转及 480p 通过。随后 360p 取源在解码前返回 app_media_unavailable，完整轮失败。缩小为仅已知 720p 的一轮也在首次取源时返回同错误；没有继续请求、变换身份或放宽权限，未确定上游不可用原因。
3. 离线合成 HEVC MP4 分别使用默认 D3D11、显式禁用 D3D11 后的 D3D12；两轮均验证实际硬件工厂、320×192 RGBA 红色像素 [254,0,0,255]、seek 后帧推进和暂停稳定。证明备用候选选择可用，不证明所有硬件或运行中故障恢复。
4. Release 常规测试 14 项通过，两个专项默认忽略并分别运行：硬件检查如上，EOS CPU 0.00% 单逻辑核；vendor 共享帧释放测试通过。Python 原生输入边界 11 项、Range/缓存/保护样本 5 项通过。
5. 本轮未取得最终默认策略的新透明截图：计划截图前已取源失败。离线颜色检查不替代透明合成验收；透明 shader/控件层未改动，已有透明验证证据仍来自此前版本。未测长时运行、GPU 显存、其他显卡和 macOS。
