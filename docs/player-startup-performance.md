## 当前结果

### 修复内容

- 旧POST模型请求在本机为HTTP200/空正文；采用固定现行GET入口及独立完整签名后，同账号同设备恢复播放。没有自动轮换入口、注册新设备、重试拒绝或改写网页登录凭据。接口与签名一起调整，未证明仅某一个头就是全部根因。
- 220/221集360–720p为ByteVC2，1080p为兼容HEVC；现在逐集解析能力，优先同档兼容编码，否则取不低于期望的最近兼容档位，并绑定该轨自己的材料。支持手选1080p；菜单只列已知兼容档位，显示实际分辨率，期望档位单独保留。没有兼容且足够清晰的片源时明确失败。额外兼容模型请求没有改善可用档位，已移除。
- 失败保留播放视图、已核对目录及当前选集；上一集/下一集和选集不再依赖解码成功，重试不重新套用旧历史。切换新集清理旧集能力列表，失败不继续空轮询；过期失败不能覆盖新请求。
- CLI控件检查补齐滚动偏移及可见区域裁剪；长菜单先滚动再按最新可见坐标选择，保留窗口边缘保护。未使用真实鼠标、键盘或焦点切换。
- 保留TLS连接复用、64KiB有界索引/256KiB常规块/2MiB缓存、旧GET停止后续拉块、最终身份核对与索引读取并行、seek期间20ms本地观察及阶段计时。NULL态解码器预热无确定整体收益，已撤回。

## 真实基线与失败实验

以实际 Windows 用户的保存身份只读恢复，在屏幕外、禁止激活且禁用自身物理输入的独立 Release 实例运行；收藏写入与进度上传均关闭、零音量。真实固定剧集首播 4975ms，页面账号恢复 3944ms 另计。源输入/管线合计 3111ms，包括 helper 1945ms、管线准备 1165ms；用户入口到加载函数之间还有约 1864ms，主要包含原有云端核对/队列和消息交接。差值不是精确的单接口耗时，也不能把它直接当作最终实测提速。

helper 中身份核对前334ms、后224ms，媒体模型/目录/设备924ms，媒体初始处理149ms。保留身份核对；后续取源优化应先继续分解模型/目录/设备及连接握手，而非替换解码器。

曾试验将账号进度辅助的设备档案交给媒体输入复用，以减少首次独立设备准备；上游返回 app_media_unavailable，发生在解码前，未取得可比较的帧。该实验已撤回，不能认定会话可以通用，也未确定设备档案与失败的因果关系。没有在拒绝后换设备重试、降级权限或继续请求其他集；本轮没有最终版本的真实首播耗时，不能宣称真实首播已变成以下本地数字。

最早在受限执行账户下的基线无法恢复用户凭据而超时，随后改为实际用户的只读后台基线；该超时不计为红果网络性能。
